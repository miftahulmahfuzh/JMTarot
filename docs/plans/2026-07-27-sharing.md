## 1. Why this workstream is different from the other seven

Every other workstream in v0.3.0 adds a screen behind the gate. V7 removes the
gate. That is the whole risk and it deserves to be said plainly before any code:

**`/s/[slug]` is the first URL in this project's history that a person with no
account, no session and no relationship with us can open.** Three fences that
have protected every line of code written so far stop existing at that path
simultaneously:

1. `requireUser()` never runs, so nothing may assume a `CurrentUser`.
2. The onboarding gate never runs, so nothing may assume a `profiles` row.
3. The rate limiter's key can no longer be `users.id`, because there is no
   user — and `src/lib/ratelimit.ts`'s own header says the honest thing: *"the
   real protection was the login gate, and that sentence is now false."* It was
   written about Google sign-in making the gate a free Gmail address. On a
   public page it is not even that.

And a fourth thing that is not a fence but is worse:

4. **A share link is a capability with no expiry.** The moment the URL leaves
   the app it is in a WhatsApp group, a screenshot, a crawler's cache and a
   phone backup. Revocation stops the *page* and cannot stop any of the rest.
   Every design decision below falls out of treating the slug as a bearer token
   rather than as a pretty id.

The second thing that makes V7 different: it is the workstream that can leak
`readings.question`. That column is the querent's own typed text, stored in
plaintext, named by `/privacy` §2.3 as stored user text, and the roadmap's own
risk table calls a question leak *"the single highest-consequence bug in this
release"*. §5 is four independent mechanisms against one bug, and they are
independent on purpose.

## 2. The slug

### 2.1 The alphabet

**Crockford base32, lowercase.**

```
0123456789abcdefghjkmnpqrstvwxyz
```

Thirty-two symbols: the ten digits and twenty-two letters, with `i`, `l`, `o`
and `u` removed. Three properties, and each of them is a reason:

- **`i`/`l`/`1` and `o`/`0` cannot be confused.** Somebody will read one of
  these aloud over a phone call, and somebody will retype one from a screenshot
  of a WhatsApp message. Neither is the common case; both are cheap to make
  survivable.
- **`u` is removed, which is Crockford's own stated reason** — it is the single
  highest-leverage character to drop for accidental obscenity in English.
- **Thirty-two divides 256 exactly**, so `byte & 0x1f` is a *uniform* draw with
  **zero rejection sampling**. A modulo over a 36- or 62-character alphabet is
  biased unless you write a rejection loop, and a biased CSPRNG in a capability
  token is the kind of bug that is invisible in every test and shortens the
  effective key length. One mask, no loop, no bias, and the argument fits in a
  comment.

Lowercase because the URL is going to sit in a chat bubble next to lowercase
prose, and mixed case in a URL is where people make transcription errors.
Crockford is case-insensitive on decode, so `normalizeSlug()` folds case and
maps the four excluded letters onto their look-alikes (`i`,`l`→`1`, `o`→`0`,
`u`→`v`). **That normalization is injective over the generated set** — a
generated slug never contains `i`, `l`, `o` or `u`, so it is a fixed point of
the map, and no two distinct generated slugs can normalize onto each other.
Without that property, normalization would be a way of turning one live link
into a lookup for a different one.

### 2.2 The length, against a computed budget

Twelve characters. **60 bits.** Here is the arithmetic rather than an assertion.

Budget assumption, deliberately absurd for this app: **N = 2,000,000 live
links** (100,000 users × 20 shares each). JMTarot currently has two users.

| chars | bits | space `S` | birthday `≈N²/2S` | blind guesses for one expected hit `≈S/N` |
|---|---|---|---|---|
| 8 | 40 | 1.10e12 | **1.8** — certain | 5.5e5 |
| 10 | 50 | 1.13e15 | 1.8e-3 (1 in 563) | 5.6e8 |
| **12** | **60** | **1.15e18** | **1.7e-6 (1 in 578,000)** | **5.8e11** |
| 14 | 70 | 1.18e21 | 1.7e-9 | 5.9e14 |

Read the guessing column against §4.4's rate limit of **120 page views per IP
per hour**:

- At 50 bits: 5.6e8 / 120 = 4.7e6 IP-hours. A 10,000-node botnet at the full
  limit finds one live reading in **20 days**. For a token with no expiry that
  is not a defence, it is a countdown.
- At 60 bits: 5.8e11 / 120 = 4.8e9 IP-hours. The same botnet needs **55 years**
  per expected hit.

Fourteen characters buys three more orders of magnitude against a threat that
is already 55 botnet-years away, and costs two characters of the thing the user
explicitly asked for. Twelve is the answer.

**The URL:** `https://www.jmtarot.site/s/` is 27 characters, so the whole thing
is **39 characters**. It fits on one line of a WhatsApp bubble at any phone
width, it is shorter than most `bit.ly` links once they carry a path, and it
does not get elided in a preview card's URL line. The `/s/` prefix rather than
`/share/` is worth four characters and is the reason it fits.

The birthday number is a nice-to-have rather than the control: `share_links.slug`
carries a `unique` constraint, so a collision is a `23505` and a retry, not a
lost link. `createShareLink` retries three times and then throws — three
retries at a 1-in-578,000 base rate is a probability nobody needs to write down.

### 2.3 The coincidence filter

With 2e6 links × 12 characters there are ~1e7 four-character windows in the
corpus, and a *specific* four-letter word appears with probability 32⁻⁴ ≈ 9.5e-7
per window — so roughly **ten hits per word, per corpus.** Crockford's `u`
exclusion removes the highest-frequency English offenders and does not remove
`a` and `e`, so it does not remove all of them.

`SLUG_DENY` is a short list of substrings, checked after generation, re-rolled
on a hit. **It is a coincidence filter, not a content filter** — the goal is
that nobody is ever handed a URL they will not send to their mother, not an
exhaustive lexicon of two languages. Do not grow it past a screen; the cost of
a miss is embarrassment and the cost of chasing it is a moderation project.

### 2.4 `slug.ts` is where the entity union lives

`SHARE_ENTITIES = ['reading', 'persona']`, `ShareEntity`, `isShareEntity()`. It
goes here rather than in `links.ts` because `links.ts` is `server-only` and the
API route's zod schema needs the guard. Same reasoning as
`src/lib/moderation/types.ts` being client-importable while `blocklist.ts` is
not.

**`slug.ts` must stay free of `process.env`.** `SHARE_BASE_URL` carries no
`NEXT_PUBLIC_` prefix, so a client component reading it through this module
would silently see `undefined` — the exact trap `localeSwitcherEnabled()`'s
header records, which "lived in `LocaleSwitch.tsx` for about ten minutes". The
URL builder therefore lives in `links.ts` (`server-only`), and **the client is
handed the finished URL in the POST response and never builds one.**

## 3. The data layer

### 3.1 `share_links`, verbatim from roadmap §4

Implemented exactly as §4 writes it, including `include_nickname default true`.
Two notes that are implementation, not deviation:

- **The column defaults are a safety net, not the product default.** The share
  sheet always POSTs both booleans explicitly, so `include_question`'s `false`
  and `include_nickname`'s `true` only ever apply to a row written by something
  that is not the sheet. That resolves the apparent tension between "the
  question is opt-in" (a product rule the sheet enforces) and "`include_nickname`
  defaults true" (a column default §4 fixes).
- **`index (slug) where revoked_at is null`** is the public read path. Drizzle
  writes it as `index('share_links_live_slug_idx').on(t.slug).where(sql\`revoked_at is null\`)`.
  The plain `unique` on `slug` stays: a revoked slug must never be re-issued,
  and a partial unique index would free it.

### 3.2 `readings.shared_at`

Set on the **first** mint, in the same transaction as the insert, and **never
cleared** — §4 says "first time a link was minted" and that is the fact it
records. It does not mean "there is a live link right now"; V6's history badge
should read it as *this has left the app before*, which is the honest thing to
show, because revoking does not un-send a screenshot. If V6 wants the live/dead
distinction it joins `share_links`, which is what the denormalization exists to
let it avoid doing per row.

### 3.3 Re-sharing after a revoke **rotates the slug**

`unique (user_id, entity, entity_id)` means one row per artifact forever. So
"share this again after revoking" has exactly two implementations and one of
them is a security bug:

- ❌ `set revoked_at = null` on the existing row. One line, obvious, and it
  **resurrects a capability the user deliberately killed.** The old URL, sitting
  in the WhatsApp group they revoked it because of, starts working again.
- ✅ `set revoked_at = null, slug = <fresh>, updated_at = now()`.

The second one is what `createShareLink` does on conflict. Write the comment;
this is the single most likely one-line "simplification" in the whole
workstream.

### 3.4 The resolver must not distinguish "deleted" from "never existed"

Roadmap §4: `entity_id` is polymorphic with no FK, so a deleted reading leaves
its link behind. `resolveShare()` therefore does two steps and collapses every
failure into one shape:

```
slug invalid          -> null
no row                -> null
revoked_at not null   -> null
artifact row missing  -> null      <- the orphan case; a 404, never a 500
artifact not shareable-> null
```

Five different facts, one answer. `notFound()` renders one page for all of
them. A stranger cannot tell a typo from a revocation from an erased account,
and that is the point — the alternative tells anyone with a slug that the
account behind it still exists.

### 3.5 Only `status = 'ok'` is shareable

VD9 bars `blocked`, `failed` and `aborted`. This plan additionally bars
`partial`, which VD9 does not name, and the reason is worth the extra line: a
`partial` body is real prose that simply stops — `CLAUDE.md` records that the
`[Bacaan terputus…]` notice never reaches `readings.body` — so a stranger
reading it cannot tell "the stream died" from "this reader is incoherent". The
one page in the product that strangers meet should not be the one showing a
truncated reading. It is the conservative direction and it is one predicate to
relax if Miftah disagrees.

Enforced **twice**: `createShareLink` refuses, and the resolver's `where` clause
requires it. The second is not redundant — it is what protects a link minted by
a future code path that forgot the first check.

### 3.6 The handle-first rule, and what cannot live in `queries/`

`queries/contract.test.ts` requires `db` as the first parameter of every
exported function under `src/lib/db/queries/**`, and forbids `react`,
`server-only` and `next/*` there. So:

| Lives in | Why |
|---|---|
| `queries/share.ts` | `insertOrRotateShareLink`, `shareLinkBySlug`, `revokeShareLink`, `liveShareLinkFor`, `bumpShareViewCount`, `publicReadingForShare`, `publicPersonaForShare` |
| `share/slug.ts` | `newSlug`, `isValidSlug`, `normalizeSlug` — no handle to take |
| `share/links.ts` | `createShareLink`, `resolveShare`, `revokeShare`, `shareUrl`, `shareOrigin`, `sharingEnabled` — reaches the singleton, carries `server-only` |

The same wall W3 hit with the Lotus cache and W5 hit with `windowBounds`. It is
not stylistic and the test will fail on it.

## 4. The public page

### 4.1 It is already inside the middleware matcher, and that is the whole locale story

`src/middleware.ts`'s matcher is
`/((?!_next/|cards/|dukuns/|favicon|icon|apple-icon|manifest|sitemap|robots).*)`.
`/s/<slug>` matches none of those exclusions, so **middleware runs**, `decide()`
returns `{kind:'next'}` once `isPublic()` knows about `/s/`, and `respond()`'s
`next` branch sets `x-jmt-locale` on the forwarded request from
`resolveForMiddleware(req, null)` — which for a stranger is
`cookie → Accept-Language → 'id'`.

**So `await getLocale()` and `await getT()` already work on the public page with
no session and no new code.** Verify this claim in Task 8 rather than trusting
it; the failure mode if it is wrong is an English page in an Indonesian browser,
which nobody notices for a month.

This is also why the manifest's cookie fallback (I13) is not needed here — the
manifest is excluded from the matcher and `/s/` is not.

### 4.2 The locale decision: **chrome from the viewer, prose verbatim from the sharer**

Roadmap §7 trap 2 says a stranger in Jakarta opening an English person's link
"should get Indonesian chrome around English prose, not a crash". This plan
takes that literally and adds the mechanism that makes it honest:

- Every string V7 renders — the eyebrow, the slot labels, the disclaimer, the
  *Try It Yourself* copy, the date — comes from `await getT()`, i.e. the
  viewer's browser.
- `readings.body` is rendered **verbatim, in `readings.locale`**, wrapped in
  `<div lang={reading.locale}>`. That attribute is not decoration: it is what
  makes a screen reader pronounce Indonesian prose as Indonesian inside an
  English document, and what makes the browser's own translate offer point at
  the right language.
- When the two disagree, one line of chrome says so:
  `share.public.otherLanguage` — *"This reading was written in another language
  and is shown as it was written."* Shown only on a mismatch.

**Why not pin the sharer's locale for the whole page?** Because the sharer's
locale is a fact about the sharer's phone, and the CTA at the bottom is aimed
at the viewer. Sending a stranger to a sign-in flow in a language they did not
ask for, on the one page whose entire job is conversion, is the wrong trade —
and it would mean the page ignores `Accept-Language`, which is the only signal
we have about them.

**Why not translate the body?** Three reasons, and the third settles it.

1. VD7: `readings.body` is immutable and the original is what was shared.
2. VD8: translation is on demand and never in bulk. A public page that can
   trigger a model call is a public page that can spend money, and it is
   reachable by anyone with a slug. **The public route must never generate
   anything.**
3. Even reading an *existing* `translations` row would be wrong here: the page
   would then render differently depending on invisible state the sharer cannot
   see, which makes the share sheet's "this is exactly what they will see"
   preview a lie. The preview promise is worth more than the convenience.

### 4.3 Nothing on the page may assume a session — including `currentUser()`

The page does **not** call `currentUser()`, even though it would safely return
`null`. Two reasons: a page whose output varies by session is a page whose
cache key varies by session, and an owner-only affordance on the public page is
a second renderer for VD10 to keep in step. The sharer previewing their own
link sees exactly what everyone else sees, which is the feature.

Mechanically, the client subtree of `/s/[slug]` must not mount `ViewerProvider`
and must not call anything that reads it. **This is the failure `curl` cannot
see** and is why §9 plans a real browser with the cookie cleared: a client
component reaching for a session context renders fine on the server and throws
on hydration, so the HTML is correct and the page is dead.

### 4.4 Rate limiting — the one new denial-of-service surface

Three keys through the existing `hit()`. No new module, no new dependency, and
`src/lib/ratelimit.ts` is not edited — `hit(key, now, max, windowMs)` already
takes all four.

| Key | Max | Window | Shape it stops |
|---|---|---|---|
| `share:view:<ip>` | 120 | 1 h | one host walking the slug space |
| `share:og:<ip>` | 60 | 1 h | the CPU-expensive one; see §7 |
| `share:view:_global` | 3000 | 1 h | a crowd, per instance |
| `share:create:<users.id>` | 20 | 1 h | mint spam; keyed on the session, so this one is the normal case |

`share:view:_global` is `hit()` called with a constant key, which is exactly
what `hitGlobal()` is — reused rather than duplicated. **`hitGlobal()` itself is
deliberately NOT called here:** its budget is the reading path's, and a viral
share link exhausting it would stop the actual product from working, which is a
worse outcome than a slow share page.

Honest caveat, inherited from `ratelimit.ts`'s header verbatim: this is
per-instance memory, best effort, and the day a link to JMTarot is posted
anywhere public the answer is `@upstash/ratelimit` on Redis. The interface is
`hit()` precisely so that swap stays local.

**On exhaustion the page renders a 429**, not a 404. This differs from
`/api/events`, which always answers 204, and the difference is justified: that
route's caller is a `sendBeacon` that cannot read a response, so a status code
there is a message to nobody. Here the caller is a person, and lying to them
with a 404 tells them their friend's link is broken. The enumeration defence is
60 bits (§2.2), not obscurity about whether a limit exists.

**No resolve cache is shipped.** A 30-second positive cache would absorb a
viral link at the cost of a 30-second window in which a revoked link still
resolves, and revocation is the highest-consequence control in the feature. The
constant `SHARE_RESOLVE_CACHE_MS` exists, defaults to `0`, and the comment says
what turning it on costs. A single-row lookup on a unique index is the cheapest
query in the schema; buy the cache when there is load to justify it.

### 4.5 `view_count` and `share.viewed` count different things, on purpose

- **`share_links.view_count`** is incremented in `after()` on every rendered
  GET, crawlers included. It is a **load and abuse signal**, not an audience
  metric.
- **`share.viewed`** fires from a `TrackView` in the browser, so it excludes
  crawlers, and it is the audience metric.

That is the same shape as `reading.completed` existing twice from two sides —
and the same payoff: a `view_count` far above the `share.viewed` count is a
crawler storm, and the reverse is a broken beacon. Document the pair in
`docs/analytics-queries.md`.

The increment is wrapped in try/catch that logs **the error's class only**. The
bound parameter here is a uuid rather than a question, so the specific risk
`flush.ts` and `log.ts` guard against is absent — but the rule is mechanical
and a mechanical rule that has exceptions is not a rule.

### 4.6 `noindex`, and no static caching

`robots: { index: false, follow: false }` on the page, same as `/terms`. A
shared reading in a Google index is a disclosure nobody chose. `og:*` tags are
unaffected — messenger crawlers read those regardless.

`export const dynamic = 'force-dynamic'` so Next never caches the render. The
OG image is cached hard and separately; see §7.4.

## 5. The privacy design — four independent mechanisms

The roadmap calls a leaked question the highest-consequence bug in the release.
One mechanism is a hope. These four fail independently.

### 5.1 The column is never selected

`publicReadingForShare(db, readingId, includeQuestion)` builds its select object
conditionally. When `includeQuestion` is false, `readings.question` **is not in
the projection**, so the value never enters the process, never enters the RSC
flight payload, and never enters a driver error's bound-parameter list.

### 5.2 The test asserts the emitted SQL, not the returned object

Asserting `result.question === null` passes for a query that selected the
column and then dropped it — which is the bug, because the value was in memory
and in the flight payload. So the integration test calls Drizzle's `.toSQL()`
and asserts the **string** contains no `question`:

```ts
const { sql: text } = publicReadingQuery(tx, readingId, false).toSQL();
expect(text).not.toMatch(/\bquestion\b/);
```

This requires `queries/share.ts` to export the query *builder* alongside the
executing function. That is a small ugliness in exchange for the only assertion
that actually covers the requirement.

### 5.3 The share sheet renders the real page before the link exists

The sheet mounts the same `<ReadingView>` the public page mounts (VD10), with
the toggles applied, **from data the sharer already has on screen** — no query,
no round trip, no second renderer. "Show the querent exactly what will be
public" is then true by construction rather than by review, and it stays true
when somebody adds a field to `ReadingView` next quarter.

### 5.4 The persona is a second, separate opt-in

`personas.body` is assembled by V8 from the onboarding answers — including
`worst_thing`, *"The heaviest thing you have watched happen"*, which `/privacy`
quotes and which `legal.test.ts` guards the wording of. V7's rules:

- Sharing a persona is a **separate mint**, `entity = 'persona'`, from a
  separate sheet on `/account`. Ticking a box on a reading share never shares a
  persona and vice versa.
- V7 renders `personas.body` **verbatim** and `personas.facts` through V1's
  glosses. **V7 has no query that can reach `onboarding_answers` and must never
  acquire one.** V8's abstraction rule (W3's D10: abstract, never restate) is
  the only thing between that answer and a public URL, and V7's contribution is
  to add no second path.
- The persona sheet's copy names what goes public, in words: life path number,
  sun sign, the card that keeps recurring, the reader whose path opened, and
  four sentences about you. If a reviewer cannot map every one of those to
  `personas.facts` and `personas.body`, the sheet is wrong.

### 7.2 The finding that changes the design: **satori cannot decode WebP**

Read out of the vendored bundle rather than from documentation:

```js
var KI="image/avif"; var YI="image/webp"; var $r="image/apng";
var An="image/png";  var en="image/jpeg";  var tn="image/gif";
var ei="image/svg+xml";
var qI = [An, $r, en, tn, ei];                 // the supported list
...
if (!qI.includes(t)) throw new Error(`Unsupported image type: ${t || "unknown"}`);
```

`image/webp` and `image/avif` are *detected* and then *rejected*. Every card in
`public/cards/` and `public/cards/thumb/` is WebP. So the card art cannot reach
the preview as it stands, and the naive implementation throws at request time —
in the one code path nobody looks at, because a missing WhatsApp preview is
invisible from inside the app.

Three options, weighed:

| Option | Verdict |
|---|---|
| add `sharp` and transcode at request time | ❌ a new dependency, a re-encode per request, and a large lambda for a preview image |
| skip the art, render type only | ❌ VD18 says the card art. A preview with no art is not the feature |
| **generate committed PNG copies at OG size** | ✅ |

**`public/cards/og/<slug>.png`, 200×300**, produced by extending the existing
idempotent `tools/normalize_cards.py` — the same script and the same rule that
already puts WebP in `public/cards/`, committed for the same reason ("so the
deploy does not need Python"). Three cards render at ~190×285 on a 1200×630
canvas, so 200×300 is exact rather than generous. Palette-quantize; measure the
total and keep it under ~1.5 MB.

### 7.3 How the art reaches satori, and the runtime correction

The brief assumed `ImageResponse` "runs on the edge and cannot read the
filesystem". **That is not fixed by the API** — the runtime is whatever the
route segment declares, and `image-response.js` picks `index.edge.js` or
`index.node.js` off `process.env.NEXT_RUNTIME` at import time. This route
declares `export const runtime = 'nodejs'`, which it must anyway, because it
queries Postgres through `postgres.js`.

Even so, the art is referenced by **absolute URL** and satori fetches it:

```tsx
<img src={`${shareOrigin()}/cards/og/${card.slug}.png`} width={190} height={285} />
```

Not `readFile(join(process.cwd(), 'public', …))`. On Vercel, `public/` is
uploaded to the CDN and its presence on the function's filesystem depends on
tracing that nothing here declares; an absolute URL is the documented pattern
and it works identically in dev against `localhost:3001`. Wrapped in the
fallback below, so a fetch failure degrades rather than 500s.

**The font.** `Cinzel-SemiBold.ttf` is committed next to the route and loaded
with the pattern Next's bundler traces:

```ts
const cinzel = await fetch(new URL('./Cinzel-SemiBold.ttf', import.meta.url))

```

Not read out of `.next/`, where `next/font/google` writes hashed filenames that
change on every font update. One file, ~35 KB. If the load throws, `fonts` is
omitted and `ImageResponse` falls back to its bundled Geist — off-brand but
rendered, which beats no preview.

**The reader is type, not a portrait.** `public/dukuns/*.jpg` is JPEG and would
decode fine, but it is a 2:1 environmental scene at full page width; scaled into
a corner it reads as mud, and it costs a second network fetch and a JPEG decode
on a CPU-metered path. The reader's **name and title in Cinzel** satisfy "the
reader" in VD18. Flagged in `## Open questions` because it is a reading of VD18
rather than the only one.

### Task 2 — `newSlug()`: CSPRNG, uniform, deny-listed

**Test** (append to the same file):

```ts
it('draws only from the alphabet, at the declared length', () => {
  for (let i = 0; i < 200; i++) {
    const s = newSlug();
    expect(s).toHaveLength(SLUG_LENGTH);
    expect(s).toMatch(new RegExp(`^[${SLUG_ALPHABET}]{${SLUG_LENGTH}}$`));
  }
});

it('is uniform enough that every symbol appears over 2000 draws', () => {
  // 2000 * 12 = 24000 characters over 32 symbols = 750 expected each.
  // A byte-modulo bias would starve the tail of the alphabet; this catches it.
  const seen = new Map<string, number>();
  for (let i = 0; i < 2000; i++) for (const c of newSlug()) seen.set(c, (seen.get(c) ?? 0) + 1);
  expect(seen.size).toBe(32);
  for (const [, n] of seen) expect(n).toBeGreaterThan(400);
});

it('does not repeat itself', () => {
  const n = 5000;
  expect(new Set(Array.from({ length: n }, newSlug)).size).toBe(n);
});

it('rerolls a slug containing a denied substring', () => {
  // Deterministic: force the generator's source to emit a denied slug once.
  expect(containsDenied('aa' + SLUG_DENY[0] + 'aaaa'.slice(0, 12 - 2 - SLUG_DENY[0].length)))
    .toBe(true);
  for (let i = 0; i < 500; i++) expect(containsDenied(newSlug())).toBe(false);
});
```

**Implement:**

```ts
/**
 * One slug. CSPRNG, uniform, coincidence-filtered.
 *
 * `byte & 0x1f` IS THE WHOLE TRICK AND IT IS NOT A SHORTCUT. 32 divides 256
 * exactly, so masking the low five bits of a uniform byte is itself uniform --
 * no rejection loop, no modulo bias. Over a 36- or 62-symbol alphabet the same
 * line is biased toward the head of the alphabet, which shortens the effective
 * key length of a capability token and is invisible in every test that does not
 * count symbols. There is one above that counts them.
 */
export function newSlug(): string {
  for (let attempt = 0; attempt < 8; attempt++) {
    const bytes = new Uint8Array(SLUG_LENGTH);
    crypto.getRandomValues(bytes);
    let out = '';
    for (const b of bytes) out += SLUG_ALPHABET[b & 0x1f];
    if (!containsDenied(out)) return out;
  }
  // Eight consecutive denied draws is ~impossible; throwing beats looping.
  throw new Error('slug generation failed the coincidence filter eight times');
}
```

`crypto.getRandomValues` is the Web Crypto global, present in Node 24, the edge
runtime and Vitest — no `node:crypto` import, so this file stays runtime-neutral.

```ts
export async function insertOrRotateShareLink(
  db: DbOrTx,
  values: NewShareLink,
): Promise<ShareLink> {
  const [row] = await db
    .insert(shareLinks)
    .values(values)
    .onConflictDoUpdate({
      target: [shareLinks.userId, shareLinks.entity, shareLinks.entityId],
      set: {
        /*
         * A FRESH SLUG, AND `revoked_at = null` IS NOT ENOUGH ON ITS OWN.
         * Un-revoking the existing row is the one-line version of this and it
         * resurrects a capability the user deliberately killed -- the old URL,
         * sitting in the group chat they revoked it because of, starts working
         * again. Rotating means revoke is permanent for that address.
         */
        slug: values.slug,
        includeQuestion: values.includeQuestion,
        includeNickname: values.includeNickname,
        revokedAt: null,
        // BY HAND. $onUpdate() does not fire inside onConflictDoUpdate.
        updatedAt: new Date(),
      },
    })
    .returning();
  return row;
}
```

## Open questions

1. **`include_nickname` defaults to `true` and this plan implements it
   verbatim.** It is the one place in the release where a personal field is
   public-by-default. §3.1 defuses it — the sheet always sends the value
   explicitly, so the column default never decides anything in practice — but if
   Miftah wants the *toggle* to start off, that is a one-line change in
   `ShareFooter` and no schema change. **Ask.**

2. **`partial` readings are unshareable and VD9 does not say so** (§3.5). One
   predicate to relax.

3. **VD18 says "the card art and the reader"; the OG image renders the reader
   as type rather than as their portrait** (§7.3). The portrait is a 2:1
   environmental JPEG that reads as mud when scaled into a corner. If the
   intent was the portrait, it is a layout change and one extra fetch.

4. **The OG image is CDN-cached for a day, so a revoked link's preview
   lingers** (§7.4). Acceptable only because VD18 keeps the prose out of it. If
   that is wrong, `s-maxage` drops to minutes and the CPU cost goes up.

5. **No resolve cache is shipped** (§4.4). If a link goes viral before the
   Redis limiter lands, `SHARE_RESOLVE_CACHE_MS` is the lever, and turning it on
   buys a window in which a revoked link still resolves. Somebody should decide
   the acceptable window *before* the night it is needed.

6. **A fifth sweep delete for orphaned `share_links`** is requested in
   `## Schema deltas`. W7 owns the route; V2 is already adding a fourth.

7. **`/s/` is a prefix in `isPublic()`.** Anything a future workstream adds
   under `/s/` is public with no further edit. Reconciliation should either
   accept that or ask for an exact `/s/[slug]` match, which is harder to write
   correctly because Next appends a hash to the OG image path.

8. **`src/lib/ratelimit.ts`'s own header says the swap to
   `@upstash/ratelimit` on Redis happens "the day a link to the app is posted
   anywhere public".** V7 *is* that day, by construction — a share URL is a link
   to the app, posted somewhere public, by design. This plan ships the
   in-memory limiter because Redis is a new dependency and a new service and
   neither is V7's to add unilaterally. **Somebody has to own that trigger
   before v0.3.0 ships**, and the honest reading of that comment is that it has
   already fired.
