## 0. The nine decisions, up front

Everything below is a consequence of one of these. Read them before the tasks.

### D-S3-1. The grid is 2 × 11, and the arithmetic is why

22 has exactly four divisors — **1, 2, 11, 22** — so 2 columns and 11 columns are
the only column counts producing a complete rectangle with no remainder. Miftah's
ruling (roadmap §8.1) is **2 columns × 11 rows**, in a phone-width column centred at
wider viewports.

**What was refused, and must not come back:**

- **11 columns.** Each card becomes a ~90px sliver at any phone width and the page
  reads as a filmstrip rather than a gallery. The art is the asset; a 90px card is
  the art thrown away.
- **4 × 6 with two non-card tail tiles.** Offered and refused. The tail tiles would
  be filler — a "browse the blog" card, a "take a reading" card — occupying the two
  slots 22 does not fill. **No filler tiles, no fake cards.** A grid of 22 artworks
  with two pieces of chrome wearing the same frame invites the visitor to tap
  something that is not a card, on the one page whose entire subject is the 22 cards.
- **4 × 5 + a 2-card last row.** A ragged final row is what a `flex-wrap` grid gives
  you for free, and it is exactly the thing "complete at every breakpoint" forbids.

**"Every row full, nothing spilling below" is a measurable property, and Task 15
measures it**: exactly 11 distinct row tops, exactly 2 tiles sharing each one, 22
tiles total. Not "it looked right".

### D-S3-2. The container maths, in the shape of `## Fan geometry`

The shell is the app's `.shell` pattern — `max-width: 520px; padding: … 16px` —
copied from `src/app/[reader]/page.module.css`. So the grid's containing block is
`min(viewport, 520px) − 32`.

```
2 columns, column-gap 12, row-gap 16, tile = card(2:3) + 8 + lore row(44)

viewport  content  column   card h    tile h   grid h (11 tiles + 10 gaps)
   320      288    138.0    207.0     259.0     3009.0
   360      328    158.0    237.0     289.0     3339.0
   375      343    165.5    248.25    300.25    3462.75      <- iPhone SE, the binding width
   390      358    173.0    259.5     311.5     3586.5
  >=552     488    238.0    357.0     409.0     4659.0       <- shell capped at 520
```

`column = (content − 12) / 2`. `card h = column × 3 / 2`. Every number above is
predicted by this plan and **asserted by `public/cards/_galleryfit.html`** — if a
measurement disagrees, the CSS is wrong, not the table.

Three consequences worth writing down:

1. **`CardFace`'s name plate is 7.6cqw of the column**, so it renders at **10.49px
   at 320 and 13.15px at 390**, against **6.84px** in the 90px draw-screen slot. The
   name on a gallery tile is 1.5–1.9× larger than the name the app already ships and
   nobody has complained about. **That is why there is no caption under the card** —
   a second copy of the name is the exact redundancy `CardDetail`'s header argues
   against and `AccountCard`'s ruling settled in the other direction only because
   the sentence beside it named the card mid-clause. Here the card wears its name and
   nothing else does.
2. **`The High Priestess` is the binding name**, 18 characters. At 320 the plate's
   text box is `138 − 2×(5cqw=6.9) ≈ 124px` and the string is ~131px at 10.49px
   Cinzel with 0.04em tracking, so it **wraps to two lines** — which is what it
   already does in the 90px slot and what `text-wrap: balance` is there for. Task 15
   asserts **≤ 2 lines**, not "1 line".
3. **The page is 3009–3587px of grid**, roughly nine phone screens. That is
   accepted: this is a catalogue, and "nothing spilling below" is a statement about
   **rows**, not about fitting a viewport. Do not "fix" it with pagination or an
   accordion — 22 items behind a *Load more* is 22 items a crawler may not reach,
   which is the release failing at its only purpose.

### D-S3-3. `minmax(0, 1fr)`, not `1fr`, and it is not decoration

`repeat(2, 1fr)` is `repeat(2, minmax(auto, 1fr))`, and an `auto` minimum is the
track's **min-content** size. The tile contains a lore link whose min-content is one
short word, so today the difference is invisible — and the first person to put an
in-flow `<img>` in a tile (a caption thumbnail, a badge, a "download" preview) hands
the track a **240px** intrinsic minimum, at which point the grid is
`240 + 12 + 240 = 492px` inside a 288px container and the page scrolls sideways on
every phone.

`minmax(0, 1fr)` plus `min-width: 0` on the tile makes that impossible. Task 15
asserts `grid.scrollWidth <= grid.clientWidth` at all four widths **and is
negative-controlled**: temporarily add `min-width: 260px` to `.tile`, confirm the
harness goes red at 320/360/375/390, then remove it.

### D-S3-4. `CardFace` and `CardDetail` are reused. `next/image` is still impossible

**Reuse them; do not write a third card renderer.** `AccountCard.tsx`'s header is a
ruling from 2026-07-28 and it settles both halves:

- The soft half — *"`CardFace` is deliberately NOT reused because the sentence beside
  the image already names the card"* — **lost**, because every other 88×132 card in
  the product wears its name and the one that does not reads as the one that failed
  to load its label.
- The hard half is **unchanged and must be satisfied rather than dodged**:
  `cardThumb()` in `src/data/deck.ts` appends `?v=${ART_VERSION}`, and `next/image`
  **refuses a local `src` carrying a query string** unless `images.localPatterns` is
  configured. `next.config.ts` configures no `images` block at all, so an `<Image>`
  here throws
  `Image with src "/cards/thumb/18_moon.webp?v=3" is using a query string which is not configured`
  and takes the page to a 500 **with a green build**. `CardFace` uses a plain `<img>`
  for its own reason (the WebP is already generated at exactly the two sizes we draw
  it at, so the optimizer has nothing to improve), so routing through it satisfies
  the constraint.

**Do not add an `images` block to `next.config.ts` to "unlock" `next/image` here.**
`next.config.ts` is S1's file in v0.4.0, and the change would put 22 serverless
image invocations in front of a page whose whole point is a fast crawl of
already-optimal assets.

**No `loading="lazy"`.** The 22 thumbs are **336KB total** (`du -sh
public/cards/thumb/`), served with `public, max-age=31536000, immutable`. That is
less than one full-size card. Lazy-loading a grid the visitor scrolls immediately
trades a smaller first payload for eighteen late paints on the page Core Web Vitals
will be measured on.

### D-S3-5. The tiles are UPRIGHT, and the overlay teaches BOTH glosses

**Every card on `/gallery` is upright.** `reversed` in this app means *this card came
out of the deck this way*, and there is no deck here. `/account` is the precedent for
the other direction and proves the rule: it passes `topCardReversedDominant`, an
orientation the card **earned** across a querent's history, and there is no earned
orientation for a stranger who has never drawn anything. A grid of 22 artworks with
six of them upside down reads as a rendering bug.

**The consequence for the gloss is the interesting part.** `cardMeaning(draw,
locale)` returns the line that matches the orientation, so an upright-only gallery
would show only upright glosses — and a catalogue that teaches half of each card is
a catalogue a lore page has to repeat. So the overlay shows **both lines, each
labelled**, and it reads **both** through `cardMeaning`:

```ts
cardMeaning({ card, reversed: false }, t.locale)   // labelled `card.upright`
cardMeaning({ card, reversed: true  }, t.locale)   // labelled `card.reversed`
```

Never `card.meaning[locale].upright`. The indirection guards two things at once
(orientation *and* locale), which is exactly why `deck.ts`'s comment says there are
now two ways to get it wrong by hand instead of one.

Labelling is what makes this legal: the artwork above stays upright, and neither line
is asserted as *the* meaning of the card on screen. An **unlabelled** pair, or a
reversed line under upright art with no label, is the contradiction the rule
forbids.

`card.reversed` (`Terbalik` / `Reversed`) **already exists** in the catalog. Only
`card.upright` is new — its missing twin. **S4 should reuse the same pair on the lore
page rather than mint `arcana.upright`**; see `## Deltas requested`.

### D-S3-6. The `CardDetail` focus bug is FIXED here, and the event is what fixes it

CLAUDE.md: **Safari does not focus a `<button>` when it is clicked or tapped**, so
`const opener = document.activeElement` on the way into a dialog captures `<body>`
on the one platform this app is built for. `AccountMenu` fixed it by taking the
opener as a prop (`returnFocusTo`); CLAUDE.md records that **`CardDetail` still has
the latent version**, with a smaller consequence "because its opener is a card in a
long list".

**On this page it is not smaller.** The opener is one of 22 tiles in a grid **3009 to
3587px tall**. Restoring focus to `<body>` teleports a keyboard or VoiceOver user
from row 9 to the top of the document, and the only way back is to re-traverse
however many rows they had already passed. That is the difference between an
annoyance and a page you cannot navigate.

**The fix, and why it is airtight rather than merely better:** `GalleryGrid` holds
one `openerRef`, and the tile's zoom handler stores **`event.currentTarget`** into it:

```tsx
onZoom={(card, opener) => { openerRef.current = opener; setOpen(card); }}
// in the tile:  onClick={(e) => onZoom(card, e.currentTarget)}
```

`currentTarget` on a click event **is** the button, whether or not Safari focused it.
Reading `document.activeElement` asks the platform a question it answers differently
on the platform we ship to; reading the event asks nothing.

`CardDetail` keeps `document.activeElement` as the fallback when the prop is absent,
so the three existing callers (`Draw.tsx`, `ReadingView`, `AccountCard`) are
**byte-identical in behaviour**. Fixing theirs is not S3's; leaving the fallback is
what makes this edit additive.

### D-S3-7. The 22 lore links are in the tile, in the initial HTML

Requirement: *a Read Lore link per card*. It goes **under the card in the tile**, not
only inside the zoom overlay.

**Why not only in the overlay.** The overlay is mounted on tap. Its markup does not
exist in the response a crawler receives, so 22 links that only exist after a
`click` are 22 internal links Google may never follow — and roadmap §1 is explicit
that internal linking from the gallery to the 22 card pages is *"the shape of the
site that outranks us"*. A link that is not in the HTML is not a link.

**The grid being a client component does not change that.** Client components are
**server-rendered** in the App Router — CLAUDE.md's own harness notes record it
(*"client components are SERVER-RENDERED, so the slot labels are in the initial
HTML"*) — so the 22 `<a href>`s are in the response body. Task 17 asserts it the only
way worth asserting it: `curl -s $BASE/gallery | grep -c 'href="/arcana/'` is
**22**.

The link is **also** in the overlay, with `from: 'zoom'` on the event, because a
visitor who has enlarged a card is the visitor most likely to want its page.

**The hrefs are built on the SERVER and passed down.** `localePath(locale, ...)` is
S2's edge-safe helper; a client component computing a locale-prefixed path would need
to know the locale, and `LocaleProvider`'s header says **no locale prop is drilled
anywhere**. `page.tsx` builds `Record<card.id, href>` once.

### D-S3-8. Nothing on this page reads the visitor. The URL is the only input

Roadmap §4.1: on a content route **the URL wins and it is the only input**. S-D10:
no cookie is set, and the response must be CDN-cacheable.

So `/gallery` is Indonesian for everybody and `/en/gallery` is English for everybody,
and **that is a requirement on S2's middleware in both directions**, not only on the
prefixed branch. `getLocale()` is `localeFromHeaders(x-jmt-locale, jmt_locale)` and
the header wins — so if middleware forwards a header resolved by
`resolveForMiddleware`'s ordinary chain (session claim → cookie → `Accept-Language`),
then **bare `/gallery` is viewer-variant**: an `en-GB` browser, or anyone carrying
`jmt_locale=en`, gets English chrome at the Indonesian canonical URL. Put a CDN in
front of that and whichever language warms the cache is served to everybody, under a
canonical tag and an `hreflang` pair that both claim otherwise.

**This is the single worst outcome available to S3, it is not S3's code, and it is
invisible to every unit test.** It is a hard requirement on S2 in
`## Deltas requested`, and Task 17 checks it with a hostile `Accept-Language` **and**
a hostile cookie.

Two smaller consequences of the same rule:

- **No `Vary: Accept-Language` anywhere near these routes.** The response varies by
  an *internal* header middleware writes, which the CDN never sees and must never key
  on. A `Vary` on a client header splinters the cache for no benefit.
- **No nested `LocaleProvider` and no `<main lang>`, unlike `/s/<slug>`.** That page
  needs both because its language comes from a database row while `<html lang>`
  follows the viewer. Here the URL pins the locale, middleware forwards it, and the
  root layout's `<html lang>` already follows it. The mechanism `/s/` needed is
  exactly what this route does not need, and mounting it anyway would ship a second
  catalog (+3.3KB gzipped, measured on `/s/`) for nothing.

### D-S3-9. No new design token, and here is the full list of what is used

`src/theme/tokens.ts` is the single source of truth and `tokens.css` mirrors it.
This page introduces **no hex, no font size and no easing curve.** What it uses,
all pre-existing:

```
--canvas (via body)  --gold  --gold-lift  --gold-text  --gold-pale
--gold-hairline  --gold-border  --gold-wash  --gold-wash-strong
--muted  --label  --faint  --text-warm
--font-display  --font-body
--fs-eyebrow  --fs-title  --fs-hint  --fs-card-title  --fs-reading  --lh-reading
--ls-title  --ls-button  --ls-slot-label  --ls-section-label
--radius-card  --radius-chip
```

Gaps are plain px in the same vocabulary the app already uses: **12** (`Slots`'
inter-slot gap), **16** (the reader picker's list gap), **8** (`.back`'s icon gap).
The `.srOnly` block is copied verbatim from
`src/app/onboarding/onboarding.module.css` — a utility class, not a token.

**Motion:** the only animation on this page is the overlay's `fade` / `rise`, and
`CardDetail.module.css` **already** gates both under
`@media (prefers-reduced-motion: reduce)`. So reduced motion is honoured by reuse,
and Task 6 must not break it.

Two things not to add:

- **No `transform` on tile hover.** A `scale(1.02)` would be motion nobody gated,
  on 22 elements. Hover is a border and a background wash, like `.service:hover`.
- **No smooth scroll-to-top, and no `scrollTo({ behavior: 'smooth' })` of any
  kind.** V5's measured trap: **a JS `scrollTo({ behavior })` OVERRIDES CSS
  `scroll-behavior` rather than defaulting from it**, so `html[data-still]` and a CSS
  media query have no say over it — `goTo` in `SwipeDeck.tsx` has to read
  `data-still` itself. This page has nothing that auto-scrolls; keep it that way, and
  if you ever add one, read `data-still` and `prefers-reduced-motion` in JS.

```ts
/**
 * A CLASS of referrer, never the referrer itself.
 *
 * Rule 2 of the taxonomy: a URL is unbounded cardinality, and an external referrer
 * is somebody else's page in our table. `internal` is worth keeping distinct from
 * `external` rather than folded into it -- on `/s/` it separates the sharer opening
 * their own preview from the WhatsApp tap that page exists for, and on `/gallery`
 * it separates an organic search arrival from somebody who was already on the site,
 * which is the one number v0.4.0 exists to move.
 *
 * ── WHY THIS IS A MODULE NOW, AND THE COMMENT IT INVERTS ─────────────────────
 *
 * `ShareViewed.tsx` said, in as many words: *"Copied from `AppLaunched` rather than
 * shared, because the two are four lines and putting them in a module would give
 * `track.client`'s import graph a reason to grow."* That was a reasonable call at
 * n = 2 and it is **inverted rather than deleted**, because the failure mode of
 * removing a comment is somebody restoring the duplication in six months.

 * of a function that classifies a security-adjacent value is where copies stop being
 * cheaper than a module. And the stated cost does not apply to this file: nothing
 * imports it from `track.client`, it has NO imports of its own, and it reaches the
 * browser as four lines either way. The graph is unchanged; only the copy count is.
 *
 * ISOMORPHIC, and the `typeof document` guard is why. Every caller is a client
 * component, but a client component is SERVER-RENDERED first, and an effect is not
 * the only place somebody will eventually call this.
 */
export type ReferrerKind = 'direct' | 'internal' | 'external';

export function referrerKind(): ReferrerKind {
  if (typeof document === 'undefined' || !document.referrer) return 'direct';
  try {
    return new URL(document.referrer).origin === window.location.origin
      ? 'internal'
      : 'external';
  } catch {
    return 'direct';
  }
}
```

```ts
 *    highest-resolution representation available, and since S5 that is
 *    `/wallpapers/<url-slug>-card.jpg` at the art's true 1024x1536 -- better than the
 *    800x1200 WebP and far better than the 240x360 thumb the page actually renders.
 *    `contentUrl` and the rendered `src` legitimately differ: one is the canonical
 *    representation of the artwork, the other is what a phone should download to
 *    paint a 138px tile. `thumbnailUrl` is where the thumb belongs.
 *
 * 2. **NO URL CARRIES A QUERY STRING.** `cardImage()`/`cardThumb()` append
 *    `?v=${ART_VERSION}` because `/cards/*` is served `immutable` for a year on
 *    non-content-hashed filenames. That is right for an `<img src>` and wrong here:
 *    every bump of `ART_VERSION` would change 22 URLs, and Google Images treats a
 *    changed URL as a new image with no history. `cardThumbPath()` is the unversioned
 *    twin (S4's `deck.ts`) and `wallpaperPath()` never versioned anything.
 *
 * 3. **`inLanguage` IS THE BARE `id` / `en`, NOT `intlTag()`.** `intlTag('en')` is
 *    `en-GB` (V6 measured it and kept it for date and time formats), and claiming a
 *    British regional variant for content nobody wrote as British is a fact a
 *    crawler will believe. The bare tag also matches `<html lang>`, which is the one
 *    other place this page declares its language.
 *
 * 4. **`license` IS OPTIONAL AND IS A CLAIM, SO THE CALLER SUPPLIES IT OR OMITS IT.**
 *    This file first shipped with both licence fields deliberately absent, because
 *    emitting `license: <some url>` for a page that states no terms is the
 *    `SearchAction` mistake with legal consequences instead of cosmetic ones. **S5
 *    then wrote the terms** -- `wallpaper.licence` plus clause 9 of `/terms` -- so the
 *    claim became true and the fields became worth having (they are what Google
 *    Images' licence badge reads). The argument is INVERTED, not deleted: if clause 9
 *    is ever removed, so are these two fields, and `undefined` is the honest value
 *    rather than a guess.
 *
 * 5. **EVERY `ImageObject`'s `@id` IS ITS CARD'S LORE PAGE PLUS `#image`**, so S4's
 *    `/arcana/<slug>` can emit the SAME node id and the two pages describe one image
 *    rather than two. `url` points at the lore page for the same reason: it is the
 *    landing page for that artwork, and a gallery of 22 images all pointing at
 *    `/gallery` gives Google Images nothing to rank per card.
 *
 * PURE, AND EVERY SIZE AND EVERY URL COMES IN AS AN ARGUMENT. These two functions do
 * not know about `@/lib/wallpaper`, `process.env`, `t` or `absoluteUrl` -- which is
 * what keeps them testable and what keeps this module's leaf discipline (S-D11) from
 * being undermined by a builder that reaches for the environment. `inLanguage` is a
 * STRING rather than a `Locale` for the same reason: `website()` already decides this
 * graph's language-tag convention and a second opinion here would put two spellings
 * of one language in one `@graph`.
 */

export type ImageObjectArgs = {
  /** English in both locales (`## Card data`). */
  cardName: string;
  numeral: string;
  /** Absolute. `/arcana/<slug>` or `/en/arcana/<slug>`. */
  loreUrl: string;
  /** Absolute, NO QUERY STRING. The highest-resolution representation. See note 1. */
  contentUrl: string;
  /** Its intrinsic size. `WALLPAPER_SIZE.card` -- passed in, never assumed here. */
  width: number;
  height: number;
  /** `image/jpeg` for a wallpaper, `image/webp` for the fallback. */
  encodingFormat: string;
  /** Absolute, NO QUERY STRING. The 240x360 thumb the page renders. */
  thumbnailUrl: string;
  /** `galleryAlt()`'s sentence. Localised. */
  caption: string;
  /** The UPRIGHT gloss, via `cardMeaning`. Localised. */
  description: string;
  /** BCP-47, from the caller. Whatever `website()` used. */
  inLanguage: string;
  /**
   * Absolute or root-relative URL of the page stating the licence -- S5's `/terms#9`.
   * **Omit it if clause 9 does not exist.** See note 4.
   */
  licenseUrl?: string;
};

export function imageObject(origin: string, a: ImageObjectArgs): JsonLdNode {
  return {
    '@type': 'ImageObject',
    '@id': `${abs(origin, a.loreUrl)}#image`,
    url: abs(origin, a.loreUrl),
    contentUrl: abs(origin, a.contentUrl),
    thumbnailUrl: abs(origin, a.thumbnailUrl),
    name: a.cardName,
    caption: a.caption,
    description: a.description,
    width: a.width,
    height: a.height,
    encodingFormat: a.encodingFormat,
    creditText: 'JMTarot',
    creator: { '@id': orgId(origin) },
    inLanguage: a.inLanguage,
    /* Both fields or neither, and `undefined` is dropped by JSON.stringify -- which is
       what makes an absent clause 9 an absent CLAIM rather than a `null` a crawler has
       to interpret. */
    license: a.licenseUrl ? abs(origin, a.licenseUrl) : undefined,
    acquireLicensePage: a.licenseUrl ? abs(origin, a.licenseUrl) : undefined,
  };
}

export type ImageGalleryArgs = {
  /** Root-relative path of THIS page, in THIS locale: `/gallery` or `/en/gallery`. */
  path: string;
  name: string;
  description: string;
  inLanguage: string;
  /** `breadcrumbList([...])`'s node, embedded inline. */
  breadcrumb: JsonLdNode;
  images: readonly ImageObjectArgs[];
};

export function imageGallery(origin: string, a: ImageGalleryArgs): JsonLdNode {
  const url = abs(origin, a.path);
  return {
    '@type': 'ImageGallery',
    '@id': `${url}#gallery`,
    url,
    name: a.name,
    description: a.description,
    inLanguage: a.inLanguage,
    isPartOf: { '@id': `${origin}/#website` },
    breadcrumb: a.breadcrumb,
    numberOfItems: a.images.length,
    associatedMedia: a.images.map((img) => imageObject(origin, img)),
  };
}
```

- **No `Set-Cookie`.** S-D10, and the mechanical reason: a `Set-Cookie` makes the

  While you are here, confirm `/s/<anything>` **still** answers

```sh
# 2. THE LOCALE PIN. The most important two commands in this task.
```
