# A6 — The blog CMS

**Workstream A6 of v0.5.0.** Migration `0011`, `blog_posts` + `blog_post_locales`,
`src/lib/content/lint.ts`, a structured block editor under `/admin/blog/**`,
`/api/admin/blog/**`, `scripts/blog-import.ts`, and the rewiring of `src/app/blog/**`,
`src/app/sitemap.ts` and `src/lib/seo/blog.ts` onto a database source.

Depends on **A1** for `requireAdmin()`, the `/admin` route group and its shell, the
middleware matcher, `events.ts` and `.env.example`. Nothing else.

**This workstream carries the highest-risk seam in the release** (roadmap §11.6), and it
is the only one that takes a file whose header says *"NO DATABASE"* in capitals and puts
a database behind it. Everything below is organised around that fact.

---

## 0. What this is, and the one thing it makes genuinely better

Two articles ship. Both were authored by an agent in a worktree, and the roadmap's third
thesis is that *prose only a git commit can change is prose that does not get written*.
After A6 an article is created, edited, published and unpublished in a browser.

**`bodyHash` and the hand-written per-locale `dateModified` are DELETED, and that is not
a loss — it is the one genuine improvement in this change.** Say it plainly, because
deleting a tripwire looks exactly like deleting a tripwire, and CLAUDE.md, the S6 notes
and `src/content/blog/index.ts:33-42` all record `bodyHash` as *"manual bookkeeping
somebody will want to delete."*

The reason it existed is stated in the same place and it is a reason about **files**:

> There is no truthful automatic source for `dateModified` — a filesystem mtime is a
> checkout artefact on Vercel, `git log` is unavailable at request time, and either
> moves on a whitespace change.

Every clause of that is true of a file and false of a row. `blog_post_locales.updated_at`
is written by the request that changed the prose, in the same transaction, and is
readable at request time. It is the truthful source that did not exist. Reconciliation
§7 ruled that *"the honest alternative is dropping `dateModified` from the structured
data, never emitting a date nobody maintains"* — A6 takes neither branch, because a third
one has appeared.

**The four committed hashes do not die with the column. They become the migration
oracle** — see §13.3. That is the honest retirement of a tripwire: it stops guarding the
prose and starts proving the move was lossless, once, and then it goes.

## 1. The two dangers, restated as binding

### 1.1 The copy lint (A-D13)

`src/content/types.ts:38` says in capitals: **THE LINT IS THE REASON THIS IS DATA.**
*"Anyone converting these files to TSX for authoring comfort switches the release's only
quality gate off, silently."*

**A6-1. A DATABASE ROW IS THE SAME HAZARD IN DIFFERENT CLOTHES, AND THE HAZARD IS NOT
"THE PROSE IS UNSTRUCTURED" — IT IS "NO TEST RUNS OVER IT."** A row keeps the typed block
union and keeps `plainText()` restoring the exact reader string, so the *shape* half of
the argument survives the move untouched. What does not survive is the mechanism:
`blog.content.test.ts`'s thirty-six cases derive every fixture from `BLOG_ARTICLES`
(`blog.content.test.ts:48-56`), so deleting `src/content/blog/**` deletes the CI lint over
the shipped prose and not merely over its source. **The lint therefore gets three callers,
not the two A-D13 names** — §6.4.

**A6-2. The Malay grep is `id`-only and the tic list is `en`-only, and running either
against the wrong half is theatre.** `vocab.ts:35-40` and W6 rule 4 both say so;
`kerana` is not a risk in English and `abundance` is not a risk in Indonesian. The
`forbidden(locale)` split in `copy.test.ts:80-88` is the shape, and `lint.ts` must
reproduce it exactly, not approximately.

**A6-3. `EN_TICS` bans The Empress's own English keyword, and the lint's scope is
`src/content/**` plus submitted bodies. NEVER the rendered page.** `abundance` is card 3's
keyword in generated `cards.json`; so are `sacred` (The Hierophant), `heal`/`healing`
(Temperance, The Star) and `shadow work` (The Devil, The Moon). *Anyone who widens the
lint to the rendered page fails on data the blog does not own, concludes the lint is
broken, and switches it off.* The mechanical consequence: **`lint.ts` takes a document,
never a page, never a slug, and never anything that could reach `cards.json` glosses.**

**A6-4. R16's condition binds A6 and A6 does not discharge it.** `plainText()` joins
spans with the **empty string** (`doc.ts:32-34`), which is the entire reason
`paragraph.text` was allowed to widen to `Inline[]`. Two tests hold it — `doc.test.ts`'s
joining assertion and `blog.content.test.ts`'s adjacency case. **If either is deleted,
revert to `text: string`.** A6 inherits that condition; §6.5 states where the adjacency
case goes when `src/content/blog/**` is deleted, because moving a test is not deleting it
and dropping it on the floor during the move would discharge R16 by accident.

### 1.2 `hreflang` reciprocity (A-D15, roadmap §11.6)

`contentAlternates()` takes **the locales that actually exist (R2)**, and
`alternates.ts:65-79` says in capitals that this is *"the parameter a future edit will
want to default to `LOCALES`. DO NOT."* A pair naming a URL that 404s is non-reciprocal
and **Google discards the whole set, silently, with nothing reporting it.**

Today `entry.locales` is a hand-written array in a committed file that a reviewer reads in
a diff. After A6 it is a query result an admin changes with a toggle, between two page
views, with no diff anywhere.

**A6-5. `sitemapLanguages()` AND `contentAlternates()` STAY ONE FUNCTION.**
`sitemapLanguages` delegates (`alternates.ts:154`), and that delegation is the only reason
the `<xhtml:link>` set in `sitemap.xml` and the `<link rel="alternate">` set in the head
cannot disagree — Google reads both and treats a disagreement as a broken group. **A6
changes what feeds them and forks nothing.** Neither signature changes.

**A6-6. THE `locales` SET IS DERIVED FROM PUBLISHED ROWS THAT HAVE A BODY, AND IT IS
DERIVED IN SQL.** Not from an intent field, not from a `locales` column, not from
`LOCALES`, and not from "the row exists". The predicate is
`status = 'published' AND jsonb_array_length(body) > 0`, and it is a `WHERE` clause rather
than a filter in TypeScript because a caller that forgets the filter is exactly the shape
that ships. There is **no `locales` column on `blog_posts`** and adding one would be
re-creating the hand-written array in a place no reviewer reads.

**A6-7. THE `id` DOCUMENT IS LOAD-BEARING FOR `x-default`, AND `contentAlternates()`
THROWS WITHOUT IT.** `alternates.ts:115-120`: *"a content path with an English document and
no Indonesian one is not a state this project has."* **A6 makes that state reachable with
one toggle** — publish `en`, leave `id` in draft — and the symptom is an unhandled throw
in `generateMetadata` on a public page, i.e. a 500 on a URL in the sitemap. Two
independent defences, both required:

1. The status transition **refuses** `publish(en)` while `id` is not published (§8).
2. The public loader treats *"`en` published, `id` not"* as **not found**, in both trees,
   so a row hand-edited in `db:studio` cannot 500 the page either.

Roadmap A-D15 covers unpublishing and does not cover this direction. It is recorded in
§20 as a roadmap gap.

## 2. Schema deltas

Two tables, exactly as roadmap §3.3 specifies, plus the two resolutions §3.3 leaves to
this plan. Migration **`0011_v12-blog-cms.sql`**, generated with
`npm run db:generate -- --name v12-blog-cms`. **No column on any existing table.**
`schema.ts` has one owner (W1's role, held by A1 for this release); this section is what
reconciliation folds.

### 2.1 `blog_posts`

| column | type | null | default | notes |
|---|---|---|---|---|
| `id` | uuid | NOT NULL | `defaultRandom()` | PK |
| `slug` | text | NOT NULL | — | **UNIQUE.** Hyphenated lowercase ASCII, English, identical in both locales |
| `date_published` | date (string, `dateCol`) | NULL | — | **NULL until the first publish of ANY locale.** Locale-invariant |
| `created_at` | timestamptz (`tsCol`) | NOT NULL | `defaultNow()` | |
| `updated_at` | timestamptz | NOT NULL | `defaultNow()` | `$onUpdate` **and by hand in every upsert** |

- `unique('blog_posts_slug_uq').on(slug)`.
- `check('blog_posts_slug_shape_ck', sql`${slug} ~ '^[a-z0-9]+(-[a-z0-9]+)*$'`)`.
  **The CHECK is not belt-and-braces over the zod schema, it is the half that survives
  `db:studio`.** Without it `What-Tarot-Is` and `what-tarot-is` are two rows, two URLs and
  two `hreflang` groups, and the only thing that would notice is a crawler.
- **`blog_posts.updated_at` is NOT `dateModified`.** `blog_post_locales.updated_at` is.
  This column moves when the slug or the publication date changes, which is a fact about
  the article and not about either document's prose. Two columns with one name and two
  meanings is the `llm_calls.latency_ms` trap (roadmap §11.2) one table over; the
  difference is written here and in the column comment.

### 2.2 `blog_post_locales`

| column | type | null | default | notes |
|---|---|---|---|---|
| `id` | uuid | NOT NULL | `defaultRandom()` | PK |
| `post_id` | uuid | NOT NULL | — | FK→`blog_posts.id` **cascade** |
| `locale` | text `$type<Locale>()` | NOT NULL | — | narrowed: W1 owns `Locale` |
| `status` | text | NOT NULL | `'draft'` | **bare `text`.** A6 owns the set: `'draft' \| 'published' \| 'unpublished'` |
| `title` | text | NOT NULL | — | `< 110` chars, by lint not by column |
| `description` | text | NOT NULL | — | 80–158 chars, by lint not by column |
| `hero_card_slug` | text | NULL | — | resolved through `cardByUrlSlug` **on save** |
| `hero_alt` | text | NULL | — | both-or-neither with `hero_card_slug` |
| `body` | jsonb `$type<Block[]>()` | NOT NULL | — | the existing five kinds; zod-validated on save |
| `created_at` | timestamptz | NOT NULL | `defaultNow()` | |
| `updated_at` | timestamptz | NOT NULL | `defaultNow()` | `$onUpdate` — **this IS `dateModified`** |

- `unique('blog_post_locales_post_locale_uq').on(postId, locale)`.
- `index('blog_post_locales_status_idx').on(status)` — the public list filters on it.
- `index('blog_post_locales_post_idx').on(postId)` — **an FK needs its own index and
  Postgres does not create one.** The `reading_cards_reading_idx` lesson: a cascade
  performed one sequential scan per deleted parent row.
- `check('blog_post_locales_hero_pair_ck', ...)` — `hero_card_slug` and `hero_alt` are
  both NULL or both present. `BlogDoc.hero` is `{ cardUrlSlug, alt } | null`, so a
  half-set pair is a shape the type cannot express and the transform would have to guess
  at.
- **`status` is bare `text` with the set in the comment**, per `schema.ts:27-33`: A6 owns
  the union and narrowing it in `schema.ts` would make `schema.ts` depend on a module that
  depends on `schema.ts`. Same shape as `moderation_flags.category` and `events.name`.

**A6-8. `$onUpdate()` DOES NOT FIRE INSIDE `onConflictDoUpdate`, AND HERE THAT IS NOT
HYGIENE — IT IS THE ENTIRE `dateModified` MECHANISM.** It applies to `db.update()` only.
Every upsert in `queries/admin/blog.ts` sets `updatedAt` by hand. Drop the line and the
column freezes at the first insert, `BlogPosting.dateModified` freezes with it, and
`sitemap.xml`'s `lastModified` freezes too — the same three-way failure
`translations.updated_at` and `personas.updated_at` both carry, recorded at
`schema.ts:737-755` and `schema.ts:1032-1040`. An integration test writes twice and asserts
the column moved.

**A6-9. `'unpublished'` IS NOT `'draft'`.** A draft was never public. An unpublished
article **was** public, may be in Google's index, may be in somebody's group chat, and its
URL must now answer 404. They differ in the sitemap, in `hreflang`, in
`blogIndexNode.blogPost`, and in whether the transition is reversible without a new
`date_published`. Collapsing them to a boolean `published` loses the distinction the
release's most dangerous interaction is built on, and §8 forbids the transition that would
launder one into the other.

### 2.3 What does not change

No column on `users`, `readings`, `events`, `translations` or `share_links`.
`src/content/types.ts` is **not edited** — not `Block`, not `Inline`, not `BlogDoc`, and
nothing above the S6 marker. `src/content/blog/**` **stays importable** until
`scripts/blog-import.ts` has run in production, then is deleted in a **separate commit**
(§0.4's non-destructive rail; a destructive migration still deploys ahead of the code that
tolerates it).

## 4. The row → document transform

One module, `src/lib/content/blogRow.ts`, PURE, no `server-only`, importing only
`@/content/types` and `@/data/types`.

```ts
export type ArticleFacts = {
  slug: string;
  datePublished: string;        // 'YYYY-MM-DD'
  dateModified: string;         // 'YYYY-MM-DD', from updated_at
  locales: readonly Locale[];   // published, with a body (A6-6)
};
export type LoadedArticle = { doc: BlogDoc; facts: ArticleFacts };
```

**A6-10. THE TRANSFORM IS A PURE FUNCTION OF A ROW AND IT IS THE ONLY PLACE A ROW BECOMES
A `BlogDoc`.** `toBlogDoc(post, localeRow)` and nothing else. Two reasons: it is what
§13.3's byte-identity oracle can be written against without a database, and it is what
stops the page reading `row.body` directly and drifting from `BlogDoc`'s shape one field
at a time.

**A6-11. `hero` IS `null` OR BOTH FIELDS, NEVER A HALF-SET OBJECT.** The CHECK constraint
is one half; the transform is the other, and it must not construct
`{ cardUrlSlug: row.heroCardSlug!, alt: row.heroAlt ?? '' }` — an empty `alt` on a hero
image is an accessibility failure that renders as a perfectly normal-looking page.

**A6-12. THE TRANSFORM DOES NOT VALIDATE AND DOES NOT THROW.** `body` is `jsonb` and the
database will hand back whatever was stored; validation happened on the write path (§7).
A transform that re-validated on every read would put a zod parse on the request path of
the pages this release exists to get indexed, and — worse — a page that threw on a row it
could not parse would 500 on a URL in the sitemap for a defect that is already committed.
The write path is the gate; `types.test.ts`'s exhaustive `switch` in `plainText` and
`Prose` is the backstop, and an unknown kind there is a compile error rather than a
runtime one.

**A6-13. `dateModified` IS FORMATTED FROM `updated_at` IN UTC, WITH `toISOString().slice(0, 10)`,
AND NEVER WITH A `Date` HANDED TO A FORMATTER.** `tsCol` is `mode: 'date'`, so the driver
returns a `Date`, and `local_date`'s trap runs in reverse here: a `Date` rendered in the
server's zone is a day out for a Jakarta edit made between 00:00 and 07:00 local, and
`BlogPosting.dateModified` is a claim in structured data. UTC is the honest choice for a
publication timestamp with no querent behind it — `llm_calls`'s own rule for a call with
no querent (§3.2). Say so at the call site.

## 6. The lint extraction (A-D13)

### 6.1 `src/lib/content/lint.ts` — PURE

Imports: `@/lib/copy/vocab`, `@/lib/content/doc`, `@/content/types` (types only),
`@/lib/i18n/locale` (types only). **No `server-only`** — the vitest suite and
`scripts/blog-import.ts` both import it, and the marker throws outside a Next server
bundle. No `process.env`, no `@/data/deck`, no `@/lib/db`, no React, no `next/*`.

```ts
export type LintClass = 'error' | 'warning';
export type LintViolation = {
  rule: string;          // the kebab-case rule name, from a closed set
  cls: LintClass;
  locale: Locale;
  field: 'title' | 'description' | 'body' | 'hero' | 'slug';
  detail: string;        // the offending word / id / path. NEVER the whole document
  excerpt: string;       // <= 60 chars of the line it was found in
};

export function lintDocument(input: LintInput): LintViolation[];
```

**A6-14. IT RETURNS AN ARRAY AND `[]` IS CLEAN. IT NEVER THROWS AND IT NEVER RETURNS A
BOOLEAN.** A boolean cannot tell an author which word; a throw cannot report the second
violation. The array shape is also what makes the assertion readable, which is not a
detail: S4 wrote the per-word form
`expect({ slug, field, word, hit }).toMatchObject({ hit: false })` and *"then it prints
`hit: true` and nothing else — vitest omits the three MATCHING properties"*
(`workstream-notes.md:2977-3002`). **Collect into an array, compare against `[]`, and
format each entry as one string.** Found by breaking the lint on purpose and reading the
output; do not un-learn it.

- **The `en`/`id` divergence proof** (no shared `cardRef` card, no shared recommended
  `/arcana/` set, at least one level-2 section the other lacks). §8.2's *"English is
  rewritten, not translated"* is a real rule and a lint cannot enforce it on a document

- **`blogEntries()`'s deterministic order.** It is now `ORDER BY date_published DESC,

**A6-16. THE SPAN-ADJACENCY RULE IS R16's CONDITION WEARING A DIFFERENT HAT, AND IT IS THE
ONE RULE THE EDITOR MOST NEEDS.** `blocks.ts:27-36`: `para(s('Lihat '), link('/gallery',
'galeri'))` renders `Lihat galeri`; drop the trailing space and it renders `Lihatgaleri` —
the block union's form of the JSX-whitespace bug that shipped three times in one afternoon
as `www.jmtarot.siteand add to your phone`. A form field trims by default and a person
editing a span cannot see a trailing space, so **the CMS makes this failure mode more
likely than the file did, not less.** The rule fires when two adjacent spans join with no
whitespace on either side and neither boundary character is punctuation, and the editor
renders the joined `phrasingText()` under every span row so the author sees the string the
lint sees.

### 6.3 What refuses what

**A6-17. THE ERROR CLASS REFUSES A SAVE. THE WARNING CLASS REFUSES A PUBLISH.** This is
the product judgement the workstream turns on, and getting it backwards makes the editor
unusable in one direction or the gate decorative in the other. A6's own argument:

- A word-list violation is a mistake at the moment it is typed and there is no draft in
  which `tempoh` is acceptable. Refusing the save reaches the author while they are still
  writing, which A-D13 correctly calls *better than CI*.
- A word floor, a description band and a title length are properties of a **finished**
  article. Refusing to save a 200-word draft is refusing to let somebody write, and what
  they do then is paste the whole thing into the field at the end, unreviewed — which is
  the failure mode the gate exists to prevent, arrived at by the gate.

`POST`/`PUT` returns `422` with the violation array on an error-class hit and stores
nothing. `POST /api/admin/blog/[slug]/status` returns `422` on **either** class when the
target is `published`. Both render the array in the editor, grouped by field, with the
excerpt.

### 6.4 The three callers

1. **`src/content/arcana/lore.test.ts`** — replaces its three inline `noneOf(...)` calls

## 7. The zod body schema (A-D14)

`src/lib/content/blockSchema.ts`. PURE. zod is already a dependency (`zod ^4.4.3`) — **no
new runtime dependency** (§9.7).

```ts
const inlineSchema = z.discriminatedUnion('kind', [
  z.object({ kind: z.literal('text'),   text: z.string().min(1) }).strict(),
  z.object({ kind: z.literal('em'),     text: z.string().min(1) }).strict(),
  z.object({ kind: z.literal('strong'), text: z.string().min(1) }).strict(),
  z.object({ kind: z.literal('link'),   path: z.string(), text: z.string().min(1) }).strict(),
]);
const phrasingSchema = z.union([z.string(), z.array(inlineSchema).min(1)]);
export const blockSchema = z.discriminatedUnion('kind', [ /* five */ ]).strict-per-member;
export const bodySchema = z.array(blockSchema).min(1);
```

**A6-18. `.strict()` ON EVERY OBJECT, AND THAT IS WHAT REFUSES THE SIXTH KIND.** zod's
default strips unknown keys silently, so a submitted `{ kind: 'paragraph', text: [...],
html: '<script>' }` would validate, store the extra key in `jsonb`, and sit in the
database until somebody wrote a renderer that read it. `.strict()` makes it a `422`.
`discriminatedUnion` refuses an unknown `kind` outright, which is what refuses
`callout` — the ask **R16 refused**, asserted absent by `types.contract.test.ts:65-77`
*because the failure mode of a refused ask is somebody granting it quietly.* **A6 does not
grant it, and there is no `html`, no `raw` and no `markdown` variant.**

**A6-19. THE SCHEMA IS CHECKED AGAINST `Block` IN BOTH DIRECTIONS, AT THE TYPE LEVEL.**
A second definition of the block union is a second definition, and the two drift the day
somebody adds a field to one:

```ts
const _toBlock: Block = {} as z.infer<typeof blockSchema>;
const _fromBlock: z.infer<typeof blockSchema> = {} as Block;
```

Both assignments compile or the build fails. This is the cheap version of finding out, and
it is the same move `types.contract.test.ts` makes with `blocks.ts` — *"checked against
S4's union rather than by restating it."*

**A6-20. `link.path` IS A BARE PATH AND THE REFUSAL IS ON SAVE, NOT AT RENDER.**
`Prose.tsx:41-54` applies `localePath()`, so a document that spells `/en/arcana/the-moon`
is wrong in one of the two trees. The save path refuses: a path beginning `#` must match
`^#[a-z0-9-]+$`; otherwise it must match `^/[a-z0-9/-]*$`, must not start with `/en/`,
must not contain `://`, and if `linkKind(path) === 'arcana'` its slug must resolve through
`cardByUrlSlug`. **Resolved on save rather than at render** (A-D14), because a dead
internal link discovered at render time is a broken page and one discovered on save is a
form error. Same rule for `cardRef.slug` and `hero_card_slug` — both become a `<select>`
in the editor, so a free-text slug is not reachable through the UI and the check is what
covers the API.

`cardByUrlSlug` lives in `@/data/deck`, which `lint.ts` may not import (A6-3). So the
resolution lives in **the route handler's save path**, beside the zod parse, not in
`lint.ts`. `bare-path`'s *shape* half is in the lint; its *resolution* half is in the
handler, and the split is stated in both files.

## 8. The publish / unpublish state machine

Per `(post, locale)`. `src/lib/content/blogStatus.ts`, PURE, unit-tested — the
`swipeDeck.ts` precedent: the whole policy in a pure module is the part `npm test` can
reach.

```ts
export function canTransition(input: {
  from: BlogStatus; to: BlogStatus;
  locale: Locale;
  idStatus: BlogStatus;      // the sibling `id` row's status, or 'draft' if no row
  bodyBlocks: number;
  violations: LintViolation[];
}): { ok: true } | { ok: false; reason: TransitionRefusal };
```

### 8.1 The transitions

| from → to | allowed | conditions |
|---|---|---|
| `draft` → `published` | yes | no violations of **either** class; `bodyBlocks >= 1`; **if `locale === 'en'`, `idStatus === 'published'`** (A6-7) |
| `published` → `unpublished` | yes | none |
| `unpublished` → `published` | yes | same as `draft` → `published`. **`date_published` is NOT rewritten** — the article was published once |
| `draft` → `unpublished` | **no** | it was never public; the state would be a lie |
| `published` → `draft` | **no** | see A6-21 |
| `unpublished` → `draft` | **no** | see A6-21 |
| `X` → `X` | no-op, `200`, **no event** | a toggle double-tapped must not write a second `admin.blog_status_changed` |

**A6-21. THERE IS NO PATH BACK TO `draft` FROM EITHER PUBLIC STATE.** `draft` means *never
public*, and that is the property A-D15's whole reciprocity argument leans on: an
unpublished URL may be in Google's index and in somebody's chat history, and an admin who
can relabel it `draft` has laundered a public URL into a private one with nothing recording
the change. The editor offers *Tarik dari publikasi* and never *Jadikan draf*.

**A6-22. UNPUBLISHING `id` UNPUBLISHES NOTHING ELSE AUTOMATICALLY, AND THE `en` URL THEN
404s BY DERIVATION RATHER THAN BY A CASCADE.** A6-7's loader rule makes *"`en` published,
`id` not"* not-found in both trees, so the `en` page 404s the moment `id` leaves
`published` — without a write to the `en` row and without a second
`admin.blog_status_changed`. The row still says `published` and that is correct: it records
what the admin asked for, and re-publishing `id` restores `en` without a second decision.
**The alternative — cascading the write — is V7's *"two kinds of stop sharing"* problem:
a UI in which the querent taps the wrong one and believes something is private when it is
not.** Here the derivation is the safe direction, because the derived answer is *less*
public rather than more. The editor labels the `en` row **Tidak terjangkau — `id` belum
publik**, or nobody will understand why the page 404s.

### 8.2 What each transition does, everywhere

All five columns are derived from the one predicate in A6-6, in the same request, with
nothing caching a copy of it.

| Transition | `sitemap.xml` | `hreflang` set on the surviving URL(s) | `blogIndexNode.blogPost` | `/blog` visible list | The URL's status |
|---|---|---|---|---|---|
| `draft` (never published) | **absent** | — | **absent** | absent | **404** |
| publish `id` (first) | `+/blog/<s>` only, **no alternates** (a one-locale path gets `null`, `sitemap.ts:233-235`) | none emitted — a group naming only the page you are on is noise a validator flags | `+` on `/blog` only | on `/blog` only | `/blog/<s>` **200**, `/en/blog/<s>` **404** |
| publish `en` (second) | `+/en/blog/<s>`; the entry now carries `id`+`en`+`x-default` | `id`, `en`, `x-default`, **byte-identical on both URLs** | `+` on `/en/blog` | on both | both **200** |
| unpublish `en` | `/en/blog/<s>` **removed** | back to none, on `/blog/<s>`, **in the same request** | removed from `/en/blog` | off `/en/blog` | `/en/blog/<s>` **404**, `/blog/<s>` **200** |
| unpublish `id` (with `en` published) | `/blog/<s>` removed **and `/en/blog/<s>` removed** (A6-22) | — | removed from both | off both | **both 404** |
| unpublish the last locale | the article is **absent entirely** | — | absent | absent | **404, never 200-with-empty** |
| re-publish | the rows return; `date_published` unchanged | restored | restored | restored | 200 |

**A6-23. `404`, NEVER `200` WITH AN EMPTY BODY, AND NEVER A `410`.** A 200 on an
unpublished article is a thin page Google keeps in its index; a 200-with-empty is worse
than either, because it looks like a working page to every check except a human reading it.
`notFound()` is what the route already calls for *"exists but not in this language"*
(`[slug]/page.tsx:139-146`) and the reasoning generalises with no change. `410` is more
truthful in principle and is refused for one reason: re-publishing is a supported
transition, and a `410` tells a crawler the resource is *permanently* gone.

**A6-24. A DATABASE FAILURE IS NOT A 404, AND THE LOADER MUST DISTINGUISH THEM.** This is
the rule most likely to be lost in a `try { ... } catch { notFound() }`. A transient
outage that answers 404 on 54 indexable URLs is a de-indexing event; a 500 is a retry.
`loadArticle` returns `null` **only** for "no such published row" and lets a driver error
propagate. Nothing on this path catches a driver error and converts it — and nothing logs
it either, because *"a postgres error quotes the failing statement and its bound
parameters"* and the bound parameter here is a slug from the URL (harmless) reached through
a path where the next person will add one that is not.

- `[slug]/page.tsx:46-53` and `workstream-notes.md:5834-5837`: *"`generateStaticParams`

So the routing-layer 404 is the only thing being given up, and `notFound()` is already the

### 9.4 The four fences, amended honestly

`[slug]/page.tsx:25-44` lists four fences and `blog.contract.test.ts` enforces them across
the subtree. **Fence 3 changes and the other three do not.**

- **NO SESSION** — unchanged, and it matters more now: a page that reads a database and a
  session is a page whose output varies by user.
- **NO COOKIE** — unchanged. The URL is still the only input to the locale.
- **NO DATABASE → ONE DATABASE MODULE, NAMED.** The fence becomes: `@/lib/db/queries/blog`
  is permitted; `@/lib/db/client`, `@/lib/db/schema`, `@/lib/db/queries/admin/**` and every
  other `@/lib/db/**` specifier are forbidden. **Named by path, exactly as
  `queries/contract.test.ts:14-17` excludes `client.ts` by name rather than by loosening
  the rule** — so a second database import is a test failure and not a shrug.
- **NO MODEL CALL** — unchanged, and now load-bearing in a new way: `/blog/<slug>` is still
  the one place a model call would have no per-user budget behind it (VD7).

**A6-27. THE FENCE'S ORIGINAL RATIONALE EXPIRES AND MUST BE REWRITTEN RATHER THAN
DELETED.** The header says *"there is no version of a database outage that makes this page
500 (roadmap §10), and no fourth route joining the three that already return 500 instead
of 204."* That is no longer true and the honest replacement is: **an outage makes
`/blog` and `/blog/<slug>` unavailable, deliberately, with a 500 rather than a 404**
(A6-24), because a 500 is retried and a 404 de-indexes. The three routes that return 500
where they should return 204 (`/api/memory/frequency`, `/api/memory/summary`,
`/api/persona`) are a different bug — those are 204-shaped endpoints where an empty answer
is correct. An article is not 204-shaped: there is no empty article.

`sitemap.xml` is the one exception and it goes the other way (§10.2).

## 10. The sitemap

### 10.1 The LEAF rule, and how much of it survives

`sitemap.ts:11-19` and `sitemap.test.ts:169-192` are the strictest fence in the v0.4.0
surface: the file may import only `@/lib/seo/origin`, `@/lib/i18n/{locale,prefix}` and
`@/data/**`, and the test asserts the absence of `server-only`, `@/lib/db`, `@/lib/auth`,
`@/lib/share`, `@/lib/i18n/catalog`, `@/lib/i18n/t` and `next/headers`. The stated reason:
*"this is the response a crawler fetches first and the one that must never 500."*

**The roadmap does not mention this collision at all** (§20, defect 1). A6's resolution:

**A6-28. `sitemap.ts` BECOMES `async` AND ACQUIRES EXACTLY ONE DATABASE IMPORT,
`@/lib/db/queries/blog`, NAMED IN THE TEST'S ALLOWLIST.** The two halves of the LEAF rule
are separable and only one of them has to bend:

- *"must not acquire the message catalog, the auth stack or the share subsystem"* —
  **fully intact.** None of those becomes reachable.
- *"must never 500"* — **preserved by a catch, not by an absence** (A6-29).

The test's forbidden list keeps `@/lib/db/client`, `@/lib/db/schema`, `@/lib/auth`,
`@/lib/share`, `@/lib/i18n/catalog`, `@/lib/i18n/t`, `next/headers` and `server-only`, and
gains `@/lib/db/queries/admin` — with `@/lib/db/queries/blog` as a **single named
exception**, so a second one fails. `expect(code).toContain("from '@/lib/db/queries/blog'")`
keeps it non-vacuous.

### 10.2 The outage rule, and why it inverts the page's

**A6-29. A DATABASE FAILURE COSTS THE SITEMAP ITS BLOG ROWS AND NEVER THE FILE.**
`publishedSitemapRows` is wrapped in a `try`/`catch` returning `[]`, with the failure
logged. That is the opposite of A6-24's rule for the pages, and the asymmetry is the whole
point:

- A page is one URL. A 500 there is a retry against one address.
- `sitemap.xml` is the crawler's entry point to **54 indexable pages**, 50 of which come
  from pure leaves and are unaffected by any outage. A 500 there costs the crawl of `/`,
  `/en`, `/terms`, `/privacy`, `/gallery` ×2 and 44 lore pages to protect the listing of
  two articles.

The catch is narrow — it wraps the one call, not the function — so a bug in
`entriesFor` still throws loudly. And it is the one place in A6 that swallows a database
error, which is why it is numbered.

### 10.3 `lastModified`, and the comment this discharges

`sitemap.ts:156-162` records a deliberate loss:

> `lastModified` STAYS `CONTENT_UPDATED_AT` RATHER THAN `revisions[locale]` … the field's
> only use is "has this changed since I crawled", which one constant per release answers
> honestly. **Worth revisiting the day an article is edited without a release.**

**A6 is that day.** `SitemapPath` gains an optional
`lastModifiedFor?: Partial<Record<Locale, string>>`, populated for blog article rows from
each locale row's `updated_at` (A6-13's formatting), and `entriesFor` prefers it over
`CONTENT_UPDATED_AT` per emitted URL. Everything else keeps the constant. This is the
second genuine improvement in the change, and it is the field's honest form: an article
edited on Tuesday now says Tuesday, on its own URL, per locale — which is the same
per-locale truth `BlogPosting.dateModified` already claims.

`sitemap.test.ts`'s byte-stability assertion (`JSON.stringify(sitemap()) === JSON.stringify(sitemap())`)
becomes `await`ed and moves to the integration project for the blog rows, because two calls
now do two reads. The **exact-set** assertion splits: the 50 non-blog URLs stay in the unit
test with the blog read stubbed to `[]` (which also proves A6-29's degraded shape), and the
blog rows get an integration case over a seeded fixture. **A `toContain` is still refused
in both halves** — `sitemap.test.ts:14-21`'s reason is unchanged.

| `paragraph` | a **span row list** (below), plus a *teks biasa* toggle that stores `text: string` for a paragraph with no emphasis |

| `quote` | span row list for `text` · `source` single-line, **required and non-empty** |
| `cardRef` | `<select>` of the 22 URL slugs · `text` single-line |

**The span row list — the one control that needed designing.** Each row:
`[kind: teks \| miring \| tebal \| tautan] [text] [path, only for tautan]`. Under the rows,
**the joined `phrasingText()` rendered verbatim in a monospace strip with a visible
middle-dot for every space at a span boundary**, plus the `span-adjacency` warning inline.

**A6-31. THE JOINED STRING IS SHOWN, WITH ITS BOUNDARY WHITESPACE MADE VISIBLE, AND THAT
IS NOT A NICETY.** `blocks.ts:27-36`'s trap is that `s('Lihat ')`'s trailing space is
invisible and load-bearing. Every HTML form control the author will use trims nothing but
*shows* nothing either, so the CMS is strictly more dangerous here than the file was: in a
file the space is at least in the diff. The monospace strip is the diff.

**No contenteditable, no rich text, no markdown.** A-D14, and §9.7's *no markdown parser*.
The editor produces the five kinds and the four span kinds and there is no text format
between the author and the JSON.

### 11.3 The preview, and the one thing it gets wrong

The right pane mounts `Prose` with the parsed blocks. It is the real renderer and that is
what makes the preview worth anything.

**A6-32. THE PREVIEW'S LINK HREFS RESOLVE IN THE ADMIN VIEWER'S LOCALE TREE, NOT THE
DOCUMENT'S, AND THAT IS ACCEPTED RATHER THAN FIXED.** `Prose` calls `getLocale()` itself
and takes no `locale` prop — `Prose.tsx:71-77` and `LocaleProvider`'s *"NO LOCALE PROP IS
DRILLED ANYWHERE"*. Adding one would reach `/history`, the draw screen and `/s/`, where
chrome-follows-viewer is correct, and would be A6 editing S4's component's invariant list
for a preview. So an `en` document previewed by an Indonesian-locale admin shows
`/arcana/the-moon` where the live page will show `/en/arcana/the-moon`. **The prose, the
structure, the emphasis and the span joining — everything the preview exists for — are
identical.** The path itself is checked by the `bare-path` rule, which is the mechanical
answer to the thing the preview cannot show. A line of admin copy says so under the pane.

### 11.4 No JavaScript

The editor is the one surface in this project where a no-JS fallback is not offered, and it
is worth stating rather than leaving to inference: the block list is inherently a client
component. The **list** page and the **status** control are plain forms and work without
it, because those are the two operations that matter when something is wrong in production.

## 12. The API routes

| Route | Method | Gate | Notes |
|---|---|---|---|
| `/api/admin/blog` | `POST` | `requireAdmin()` → **404** | Create. Body: slug + one locale document. Lint + zod. `201` / `422` |
| `/api/admin/blog` | `PUT` | ″ | Update one `(slug, locale)`. Lint + zod. `200` / `422` |
| `/api/admin/blog/[slug]/status` | `POST` | ″ | `{ locale, to }`. Runs the state machine and the lint. `200` / `409` / `422` |

- **`404` on refusal, never `403`** (A-D2), *"a deliberate departure from `requireUser()`,
  which returns 401/403"* — the comment goes at the call site or somebody restores
  consistency.
- **Both declare `runtime = 'nodejs'` and `maxDuration`** (§4.2). *"Every admin request is
  a cold one, because there is one admin and no warm instance"*, and a write is *"one of
  the few things likely to be the request that wakes a suspended compute."* Paired with a
  bound on the client: the editor's fetch has an `AbortSignal.timeout()` and a stated
  failure state, because **a bigger `maxDuration` unpaired with a client bound has only
  made the hang longer.**
- **One transaction per save**: `blog_posts` upsert then `blog_post_locales` upsert, both
  setting `updatedAt` by hand (A6-8). A publish sets `blog_posts.date_published` in the
  same transaction when it is NULL.
- **No `admin_access_log` row.** A1's audit primitive records privileged reads of *another
  person's* data (A-D16). A blog save is an admin writing public content the admin
  authored; `admin.blog_saved` and `admin.blog_status_changed` are the record, and
  `blog_post_locales.updated_at` is the timestamp. Recorded because "audit everything" is
  the reflex and an audit table that fills with routine writes is an audit table nobody
  reads.
- **The lint and the zod parse run before anything is written**, and a `422` writes nothing
  — not a draft, not a partial row. A stored `Block[]` the renderer cannot render is a 500
  on a public page with the row already committed (A-D14).

## 13. `scripts/blog-import.ts`

**A script, not a migration** (§0.4: *no migration in this project inserts a row*), on the
`db:seed` precedent. Added to `package.json` as `"blog:import": "tsx scripts/blog-import.ts"`.
**Not in `npm run build`.**

### 13.1 The rules it inherits from `scripts/**`

- **No top-level `await`** — there is no `"type": "module"`, so tsx transforms to CJS.
  `async function main()` + `main().catch(...)`.
- **Never imports `@/lib/db/client`** — it starts with `import 'server-only'`. It builds
  its own postgres.js client and `config({ path: '.env.local' })`s, exactly as `db-seed.ts`
  does.
- It **does** import `BLOG_ARTICLES` from `@/content/blog`. It is the last consumer, and
  the deletion commit deletes the script with the registry.

### 13.2 What it does

1. Reads the four committed documents from `BLOG_ARTICLES`.
2. **Runs `lintDocument` on each and refuses to insert on any `error`-class violation**,
   printing the array. This is the fourth caller in effect (§6.4) and its purpose is that
   the import cannot introduce prose the API would have refused.
3. Upserts `blog_posts` on `slug`, then `blog_post_locales` on `(post_id, locale)`.
4. **Writes the committed dates, not `now()`** — see A6-33.
5. Sets `status = 'published'` on all four.
6. Prints a per-document summary: slug, locale, word count, block count, the sha256 the
   oracle expects, and whether the row was inserted or updated.

**A6-33. IT WRITES `date_published` AND `updated_at` FROM THE COMMITTED VALUES, NOT FROM
THE CLOCK.** All four documents carry `datePublished: '2026-07-29'` and
`dateModified: '2026-07-29'`. An import that let the defaults fire would move
`BlogPosting.dateModified` on four indexed pages to the day we migrated, and
`sitemap.xml`'s `lastModified` with it — announcing to every crawler that four articles
changed when not one word did. That is a spam signal for a database migration, and it also
destroys §13.3's oracle, which is the only proof the move was lossless. `created_at`
likewise.

**A6-34. IT REFUSES TO OVERWRITE A ROW AN ADMIN HAS SINCE EDITED, AND `--force` IS THE ONLY
WAY PAST IT.** The script runs in production and will be run twice — the second time by
somebody checking whether the first worked. If `blog_post_locales.updated_at` is **newer**
than the committed `dateModified`, the row has been edited through the CMS and re-running
the import would silently revert an author's work. It skips that row, says which and why,
and exits non-zero if any row was skipped. `db-seed.ts`'s guards are the shape (*"this
script DELETES before it inserts and both failure modes it prevents are
unrecoverable"*), and this one is the same category with a smaller blast radius.

There is **no** `127.0.0.1` guard and no `NODE_ENV` refusal, unlike `db-seed.ts`:
production is where this script is *meant* to run. A6-34 is what makes that safe.

### 13.3 The acceptance test for the whole workstream

**A6-35. THE TWO IMPORTED ARTICLES RENDER BYTE-IDENTICALLY TO TODAY'S OUTPUT, AND THIS IS
CHECKABLE PRECISELY BECAUSE `Prose.tsx` IS UNCHANGED.** `Prose` takes `blocks` and nothing
else, so **deep-equality of `body` is byte-identity of the rendered prose.** Three layers,
in increasing cost:

1. **Unit, no database — `blog.import.test.ts`.** For each of the four documents, run the
   committed `BlogDoc` through the row-shape transform and back through `toBlogDoc`, and
   assert `toEqual` against the original. Then compute
   `sha256(JSON.stringify([title, description, hero, body])).slice(0, 12)` on the
   round-tripped document and assert it equals the committed `bodyHash` —
   `fd66e5580bbb`, `79b11b6ed3d9`, `dd979b02e6e4`, `9063906f8f97`. **This is `bodyHash`'s
   honest retirement**: it stops being a live tripwire and becomes a one-time migration
   oracle, and it dies with the deletion commit. That expiry is stated here because roadmap
   §10.2 treats this as a permanent acceptance test (§20, defect 12).
2. **Integration.** Run the import against `jmtarot_test`, then assert `loadArticle`
   returns a `LoadedArticle` whose `doc` deep-equals the committed `BlogDoc` and whose
   `facts` carry `datePublished: '2026-07-29'`, `dateModified: '2026-07-29'` and
   `locales: ['id', 'en']`. Then assert `blogPostingNode()` built from the row output
   deep-equals `blogPostingNode()` built from the committed registry, for all four
   documents — that covers `headline`, `description`, `datePublished`, `dateModified`,
   `wordCount` and the `#hero` `ImageObject` in one comparison.
3. **`curl`, before and after.** `tools/seo/crawl.sh` over the six blog URLs against
   `localhost:3001`, saved before the rewire and diffed after. **This is the real
   byte-identity check and it is the cheap one.** Anything the first two miss — the ToC, the
   `<time>`-less meta line, the `PublicShare` canonical, the JSON-LD's serialisation — shows
   up in the diff. An empty diff on all six is the workstream's done condition.

  double-tapped toggle would otherwise read as two decisions.
- `track()` returns `void` and is never awaited. Server-side import from
  `@/lib/analytics/track`.
- **No `admin.blog_deleted`** — there is no delete (A6-21).
- **No `blog.published` public event.** Nothing a querent does.

## 20. Defects and gaps in the roadmap

Blunt, because the reconciliation is where these get resolved and a plan that quietly
worked around them would hide them.

1. **§6 and §7 list `sitemap.ts` as A6's to change and never mention that
   `sitemap.test.ts:169-192` forbids `@/lib/db` and that `sitemap.ts:11-19` calls itself a
   LEAF that "must never 500".** This is the single largest omission in the A6 contract.
   §10 is the resolution.
2. **Nor that `blog.contract.test.ts:100-118` forbids `@/lib/db` across the whole
   `src/app/blog/**` subtree**, with a written rationale about roadmap §10's "no fourth
   route that 500s". §9.4 is the resolution and it requires that rationale be **rewritten**,
   not deleted.
3. **`generateStaticParams` + `dynamicParams = false` must be DELETED and the roadmap does
   not say so anywhere** — not in A-D14, not in §7's A6 paragraph, not in §12. Worse,
   `blog.contract.test.ts:138-141` asserts both strings are present, so the contract test
   fails on the correct implementation. A6-26.
4. **A-D15 covers unpublishing and misses the opposite direction.** `alternates.ts:115-120`
   makes `contentAlternates()` **throw** when the `id` document is absent, so publishing
   `en` first is a 500 on a public URL in the sitemap. A6-7 defends it twice.
5. **§7 A6's build list names only `queries/admin/blog.ts`.** A public read module is
   required, must not live under `admin/`, and the reason is a one-edit-away leak of a
   draft onto `/blog`. §9.1.
6. **§6 does not list `ContentLocaleLink`**, which renders a reader-facing link to
   `/en/blog/<slug>` unconditionally. A6 makes that a 404 for the first time. Seam 7.
7. **A-D13's "two callers" leaves the shipped prose unlinted in CI.**
   `blog.content.test.ts`'s thirty-six cases all derive from `BLOG_ARTICLES`, so the
   deletion commit removes the gate over the two articles that are live in production, not
   just over their source. Three callers are required. §6.4.
8. **A-D13 does not distinguish rules that are facts about an article from rules that are
   facts about the two launch articles.** The orientation anchors, the ≥1100-word floor and
   the `en`/`id` divergence proof would each refuse every future article if ported
   literally. A6-15.
9. **§3.3 gives `blog_posts` an `updated_at` with `$onUpdate` and also calls
   `blog_post_locales.updated_at` "this is `dateModified`".** Two columns, one name, two
   meanings — the same defect §11.2 names for `llm_calls.latency_ms`, one table over and
   unflagged. §2.1 states the difference.
10. **§3.3 does not constrain the slug's case or shape.** Without a CHECK,
    `What-Tarot-Is` and `what-tarot-is` are two rows, two URLs and two `hreflang` groups,
    and `db:studio` is the path that gets there. §2.1 adds it.
11. **§3.3 gives `blog_post_locales` no index on `post_id`.** It indexes `status` and the
    unique `(post_id, locale)` covers lookups, but the cascade from `blog_posts` does not
    use the unique index efficiently in every plan — and §3.2 states the rule for
    `llm_calls.reading_id` in capitals while omitting it here.
12. **§10.2 treats "the two imported articles render byte-identically" as a permanent
    release acceptance test, and it cannot be one.** It compares a database row against a
    committed file, and §0.4 requires the file be deleted. It is a **migration oracle with
    a stated expiry**. §13.3.
13. **A-D18's `admin.blog_saved.lint_violations` is ambiguous** — a refused save writes no
    row and fires no event, so the prop is only meaningful for accepted saves. §14 resolves
    it; the roadmap should say.
14. **§4.1 lists `POST` create and `PUT` update on one route and a separate status route,
    but never says the lint runs on the status transition too.** It must: a warning-class
    violation is exactly what a publish must refuse (A6-17), and *"Lint runs here"* is
    written only against `/api/admin/blog`.
15. **§0.5 and §10.1 assign loop 3 at 1440px to A4 alone.** A6's editor is the second
    desktop-first surface in the release and the more layout-dependent of the two. §17.
16. Minor: **§7 A6 says "unpublishing `en` removes it from `blogPostingUrl`'s siblings"**.
    `blogPostingUrl` (`seo/blog.ts:53`) is a pure two-argument URL builder with no sibling
    concept; the function that carries the sibling set is `contentAlternates()`, and
    `blogIndexNode` is named correctly in the same sentence.
